If the ltrb output and the class logits are exported raw (split head, decode on the CPU in numpy) does the INT8 model meet the FP16 accuracy?
Model and method: ppe5_yolov8n_nodfl_100ep_s0 weights/best.pt, build_split.py (two raw outputs boxes 1x4x8400 ltrb distances and scores 1x5x8400 logits, decode_split with reg_max inferred from the box channels, tests/test_split_head.py), INT8 with the calibration list of baseline seed 0 (dataset.txt of ppe5_yolov8n_baseline_100ep_s0, the same as every INT8 export), FP16 build for the control. Evaluated through the board dump path with metadata split_head true (evaluate.py --backend rknn --variant split).
Validity controls (read before any INT8 number), same as A1: V-PC decode_split of the exported ONNX against output0 of the standard weights/best.onnx (onnxruntime, random input) at most 0.01, V-board the split FP16 model has css_test AP50-95 within 1.35 pp of the standard FP16 of A2 (49.33). If a control fails no INT8 result is read.
Statements (css_test, AP50-95, AP NoHelmet, AP Vest, pp): N2-1 A2 split INT8 minus A2 split FP16, minus A2 standard FP16 (49.33), minus A2 default INT8 (36.75).
