ADDENDUM written 2026-10-31T18:29:23+07:00, still before any recipe mAP data exists, after the advisor review of the design.
(1) Output grid (a property of the step-1 quantization cfg of SiLU seed 0, read from scratchpad/hyb_probe, arithmetic not mAP data): the int8 tensors /model/model.22/Concat_1_output_0_sw, /model/model.22/Sigmoid_output_0_rs and output0-rs have scale about 0.0039 to 0.0041, zero point -128 and range [0, 1.0 to 1.05]; the pre-sigmoid class tensor /model/model.22/Concat_1_output_0-rs has range [-7.0, 4.7] (scale 0.046); the box coordinates are in the same output0 tensor, normalized by the input size, so one step is about 0.004 of 640 px, about 2.6 px. A class score below about 0.002 therefore rounds to 0 and is removed by the evaluation confidence 0.001. The ReLU cfg is read the same way by the build script, which asserts that the tail names exist and are int8.
(2) Two recipes added: h3 = float16 only for the output tail (the exact tensors /model/model.22/Concat_1_output_0-rs, /model/model.22/Concat_1_output_0_sw, /model/model.22/Sigmoid_output_0_rs, output0-rs, output0_int8), h4 = h2 plus the h3 tail. h1 and h2 alone cannot touch the output grid, so a small recovery of h1 or h2 does not exclude the output rounding. Reading rule: compare h1, h2, h3, h4 in the statements R-b and R-c without a label that names a cause.
(3) mmse and kl: a probe build (not evaluated) of SiLU mmse with the 300 image list was killed by the operating system for lack of memory (return code 137 after 401 s, PC with 15.6 GB). EXPERIMENT 2 (written 2026-10-31T19:24:01+07:00, after seeing experiment 1 data of the recipes base, kl, h1, h2, h3, h4, auto; the advisor reviewed this design). Box coordinates are in the same int8 tensor chain as the scores: in the step-1 cfg the pixel-space box tensors have scale 0.31 to 0.63 and the normalized output0-rs 0.0041, about 2.6 px per step, and none of the recipes of experiment 1 touched the box-decode path. Class-output rounding is not supported by h3 and h4. Box precision is untested.
Experiment 2 recipes, SiLU seed 0 only (diagnosis), same calibration, same ONNX, same evaluation: h5 = float16 for the box-decode tail only (15 int8 tensors: the four dfl tensors, Slice_output_0-rs, Slice_1_output_0-rs, Sub_output_0-rs, Add_1_output_0-rs, Sub_1_output_0-rs, Add_2_output_0-rs, Div_1_output_0-rs, Concat_2_output_0-rs, /Div_output_0-rs, output0-rs, output0_int8), h6 = h5 plus the whole box branch (model.22/cv2.), c_all = every int8 tensor except the input stays float16 (validity control).
Validity statement V: the pipeline (normalized ONNX, hybrid build, metadata, dump) is 'valid for bisecting' only when c_all is within the SiLU seed range 1.35 pp of the FP16 model on css_test AP50-95, otherwise 'not valid' and no bisect result is read.
Statement R-e: a recipe 'recovers' when its AP50-95 minus base is larger than 1.35 pp (the SiLU seed range of rule.txt) and AP50 minus base is larger than 1.35 pp too, otherwise 'does not recover'. No cause is named from h5 or h6 alone. If c_all is valid and neither h5 nor h6 recovers, the loss is labelled 'vẫn chưa biết' (budget of the task is two experiments). Only a recipe that recovers is run on ReLU (R-c).
Limits: SiLU only, one seed, the scoring of c_all floods the anchors (all classes float), the evaluator NMS time limit is raised to 60 s per image (Protocol v1 code change recorded in the docs, earlier results unchanged).
