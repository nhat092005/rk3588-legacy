Activation variants rule (addendum to rule.txt), written 2026-10-31T13:18:02+07:00 before any result of the variant runs exists. Not from a source. Not reviewed by the user. Scope: user approval of 2026-10-31 ("làm đầy đủ các biến thể luôn"), advisor-reviewed design in tmp/2026-10-31_phase2b-variants-design.md. The 1.0 pp, 5 percent and 50 percent thresholds are the approved ones of gate G4 and are not changed.
Candidates (seed 0 each, INT8 conclusion dtype, 1 seed): V1 LeakyReLU with negative slope 0.1 (ai/models/yolov8n_leakyrelu/yolov8n_leakyrelu.yaml, 100 epochs). The slope is one project choice, a convention of Darknet YOLO configs, not taken from T1 or T2 (the T1 entry has no slope constraint) and there is no sweep. V2 ReLU6 (yolov8n_relu6.yaml, 100 epochs). V3 ReLU 200 epochs (yolov8n_relu.yaml, config ppe5_yolov8n_relu_200ep.yaml). Control: SiLU baseline 200 epochs seed 0 (ppe5_yolov8n_baseline_200ep_s0), descriptive. All initialised from yolov8n.pt, trained with the same Ultralytics settings as the baseline (only the model yaml and the number of epochs differ), exported with the calibration list of baseline seed 0 (export_npu.py --calib-from) and evaluated as in rule.txt.
Pre-check (not a verdict): an FP16 RKNN build of the untrained yaml (nc 80) shows the fused op names before training: V1 51 ConvLeakyRelu and 6 ConvLeakyReluAdd, V2 57 ConvClip and 8 separate Add rows, CPU rows only InputOperator, Transpose, OutputOperator. The verdict of G3 comes from the trained INT8 build.
Gate G1 mapping rule (fixed now, the same as for ReLU): a fused name maps to the Operator List entry ConvolutionXxx by name. A fused name with an Add (ConvLeakyReluAdd, ConvReluAdd) has no entry of that name, so G1 is partial and the best possible label is 'Chưa biết' even when A, B and C pass. V2 has no fused Add (pre-check), so its G1 can pass if the trained build confirms it.
Statements, css_test, per candidate:
V-C gate C: difference candidate minus SiLU seed 0 (100 epochs, the approved deployable baseline) in pp for AP50-95, AP NoHelmet, AP Vest at INT8. C passes only when all three differences are at least minus 1.0. FP16 is a reference, FP32 descriptive.
V-E for V3 only: the same differences against the SiLU 200 epoch control, as description next to V-C. If V3 passes V-C the wording is 'ReLU 200 epoch đạt', never 'đổi activation đạt', and the control comparison is stated beside it.
V-S the V-C differences read against the SiLU seed range and the ReLU seed range of rule.txt and rule_relu_seeds.txt, as description.
Labels per candidate: Giữ when G1 to G4 pass, Loại when a step fails (the first failing step is named), Chưa biết when the steps did not all run or G1 is partial with A, B, C passing.
Context recorded before the runs (val mAP50-95 in metrics.csv, descriptive): SiLU 100 epochs 0.4508 at epoch 50, 0.5049 at 80, 0.5223 at 100. ReLU 100 epochs 0.3993, 0.4653, 0.4835. Both still rise between epoch 90 and 100. Ultralytics patience is 100, so a 200 epoch run is expected to run the full 200 unless val mAP does not improve for 100 epochs (the actual number of epochs is read from metrics.csv).
Latency (A and B) of the variants is a separate interleaved run with its own rule (experiments/npu/operator_support/onboard_g4v/ppe5_yolov8n_baseline_100ep_s0/rule.txt).
Limit: one seed per candidate, one split of 82 images, ReLU6 and LeakyReLU slope are single points.
Budget: experiment 1 per candidate.
