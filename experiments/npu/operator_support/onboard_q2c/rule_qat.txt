Question: does QAT of the split-head SiLU model give a pure INT8 NPU model that reaches the FP16 accuracy, with the same criterion as A1?
Model and method (ai/npu/operator_support/qat_split.py, ai/core/rknn/qat_split.py): SiLU seed 0 best.pt, unfused model with BN in train mode, FX-traceable wrapper (C2f static slices, head returns raw boxes and scores), prepare_qat_fx with the qconfig of UG p127 (activation FakeQuantize MovingAverageMinMaxObserver 0 to 255, weight per-channel affine int8), 6 epochs, batch 8 (batch 16 runs out of memory on the 4 GB GPU), SGD lr 1e-4 momentum 0.937 nesterov weight decay 5e-4, gradient clip 10, observers disabled from epoch 5, BN statistics frozen at epoch 6, Ultralytics train augmentation and detection loss on the raw outputs, no AMP, seed 0. Then convert_fx, torch.jit.trace, rknn.load_pytorch, build(do_quantization=False), export. No hyper-parameter is changed after seeing results. The model is evaluated through the split dump path (metadata split_head true, CPU decode) with evaluate.py --precision int8 --variant qat.
Statements (css_test, AP50-95, AP NoHelmet, AP Vest, pp): Q-1 QAT minus FP16 (49.76), minus A1 split PTQ INT8 (49.84), minus int8h5 (49.66), minus default int8 (36.75). 'meets the criterion' when AP50-95 is at least 48.41 (FP16 minus 1.35 pp, the criterion of rule_split.txt, new and unreviewed). Q-2 whether the exported RKNN graph is INT8: dtype counts of the layer table of the build log (NPU INT8, NPU FLOAT16, CPU). Q-3 the training log (mean loss per epoch, seconds). If the load, the build or the evaluation fails the label is 'vẫn chưa biết' with the failure recorded, and the torch version gap is named as a possible reason only if the error message points to it.
Limits: one seed, one QAT run, SiLU only, 6 epochs (short fine-tuning), PTQ split already meets the criterion, so QAT can only tell whether it matches it, not exceed FP16 much. NPU time and coverage of the QAT model are not measured here (budget), only accuracy and the layer table.
Budget: two experiments (training and evaluation count as one).
