Split-head rule (A1 of phase 2d), written 2026-10-31T23:56:20+07:00 before any split-head data exists (the decode unit test tests/test_split_head.py ran on PC only). Not from a source. Not reviewed by the user (user approval of 2026-10-31 for QAT and quantization-friendly architectures). Reviewed by the advisor (results/notes/phase2d_design.md). T1 precedent: the YOLOv5 demo moves post-processing to the CPU (rknn_yolov5_demo/README.md:13) and the guide says removed post-processing subgraphs run on the CPU (UG232 p168), results/notes/phase2d_source_facts.md.
Question: can a pure INT8 NPU model (no float16 tensor in the NPU graph, box decode on the CPU) reach the FP16 accuracy, and what does it cost in total time?
Model: SiLU baseline seed 0 (ppe5_yolov8n_baseline_100ep_s0), no retraining. build_split.py exports the fused model through the head's own forward_head as two outputs boxes (1 x 64 x 8400, DFL logits) and scores (1 x 5 x 8400, class logits) and builds with the Ultralytics INT8 settings and the calibration list of baseline seed 0. The CPU decode is ai/board/split_decode.py (DFL softmax expectation, dist2bbox xywh, times stride, sigmoid). Evaluation uses the dump path with the metadata key split_head: true: expected normalized flag False on the board (load_model) and on the PC (RknnDumpBackend), boxes in pixels.
Validity controls (read before any INT8 number): V-PC the float decode of the exported ONNX against output0 of the standard weights/best.onnx (onnxruntime, random input) has a maximum absolute difference of at most 0.01 (recorded in recipe.json), and tests/test_split_head.py passes. V-board the split-head FP16 model evaluated through the dump path has css_test AP50-95 within 1.35 pp of the standard FP16 (49.76). If either control fails the pipeline is not valid and no INT8 split result is read. The 1.35 pp bound is the INT8 seed range of rule.txt (eval_g4), a new use, unreviewed.
Statements (css_test, AP50-95, AP NoHelmet, AP Vest, pp), if the controls pass:
S-1 split INT8 minus FP16, minus int8h5 (49.66), minus default int8 (36.75). 'meets the criterion' when AP50-95 is at least 1.35 pp below FP16 or higher (at least 48.41), a new unreviewed criterion for 'pure INT8 reaches FP16'; the approved gate C against SiLU stays the reference for the label and int8h5 is the deployable reference.
S-2 reading rule, fixed now: h5 kept the DFL logits and the decode arithmetic in float16 together. The split model puts the DFL logits back to INT8 and moves only the arithmetic to float. If S-1 meets the criterion, the decode arithmetic tail is implicated, if it does not, the INT8 quantization of the DFL logits (and the class logits) is implicated. No mechanism beyond that is named.
S-3 time, P2 interleaved run (as onboard_q2i, SiLU seed 0 only, models int8, int8h5, split INT8, CORE_0 and CORE_0_1_2, 2 sessions each, same order in both rounds, benchmark_npu.py --variant split for the split model): NPU time = median of the two session medians. CPU decode time = median and p95 of ai/board/bench/bench_decode.py (200 decodes of random (1,64,8400) and (1,5,8400) arrays) on the board under taskset on CPU4, frequencies locked. Total = NPU time at CORE_0 plus decode median. The split model is compared with int8h5 on the total, not on the NPU time alone.
S-4 descriptive: kept_anchors, the scoring time of the PC evaluation, decode_ms_median of the dump meta (unpinned, during evaluation).
Limits: one seed, SiLU only, no retraining, one board, P2 not approved, the decode is numpy (a C implementation would be faster, not measured).
Budget: two experiments for A1 (controls and INT8 evaluation count as one, the latency run as the second).
